# 开发过程纪律（dev-process）

本 skill 把《开发过程经验蒸馏》固化为执行协议：经验库（`../开发过程经验蒸馏.md`）回答"为什么"，本 skill 回答"现在做什么、怎么算做完"。每条规则标注来源（源 §x.x），badcase 证据查经验库 §7。

## 1. 目的与边界

**做**：

- 任何编码任务的四阶段强制工作流与完成门禁；
- 把"自测""完成""修好了"翻译成机器可判定清单，逐项留证据。

**不做（反边界）**：

- 不替代技术方案设计与 PRD 生成（各有专属 skill）；
- 验证/分析类任务不构成实现授权，read-only 就是 read-only；
- 未验证不得描述为通过；占位实现必须显式失败（exit + 说明），不得静默跳过；"骨架可构建"≠"业务可交付"（源 §6.3）；
- 项目业务规则、命名、口径不在本 skill 内——以项目 AGENTS.md 与事实源为准。

## 2. 触发条件（任一即适用）

- 新功能 / 竖切 / 模块开发；
- 缺陷修复（含验收轮报回的缺陷）；
- 数据库结构变更、种子或演示数据脚本；
- 框架或核心依赖大版本升级；
- 链路含模型（LLM）输出 → 额外加载 `../ai-feature/SKILL.md`；
- 前端页面、交互、会话或权限相关变更；
- 镜像 / 编排 / CI / 网关 / 环境配置类修改；
- 执行任何写着"开发完自测直到交付"的任务书。

## 3. 事实源与读取顺序

开工固定顺序：① 仓库根 AGENTS.md → ② 最近一级目录 AGENTS.md → ③ 本 skill → ④ `git status` → ⑤ 需要归因时查经验库 §7 证据表。

事实源职责（聊天记录、截图、Mock、原型只是线索，不是事实，源 §1.3）：接口契约 = Controller DTO + 错误结构 + 契约测试；需求范围 = PRD；架构边界 = 技术方案；数据库结构 = 基线 + 增量 SQL；验证证据 = 验证记录。同一事实只有一个正式来源；文档冲突时裁定哪方迁移，并声明过渡期的唯一权威源。

## 4. 必填输入（缺则停止询问，不得编造）

1. 目标行为 + 验收场景（任务书或等效描述）；
2. 受影响契约 / 事实源位置；
3. 交付物白名单（本任务允许修改哪些目录）；
4. 验证环境可用性——只检查凭据/服务的**存在性**，不读取、不打印秘密值。

任务书只写"开发完自测"→ 先展开为机器可判定 DoD 再开工（见 5.0.4）。引用清单必须写成"按 X 清单**逐项执行并输出记录**"；"参考 X"不构成触发——知识以文档形态存在时是被动知识，不点名就不会被读取（源 §1.5）。

## 5. 强制工作流

### 阶段 0 · 开工前置（全部完成才许动代码）

- [ ] 0.1 完成第 3 节读取顺序；`git status` 干净或已声明存量改动。
- [ ] 0.2 书面声明五要素：目标行为 / 验收场景 / 不变行为 / 受影响契约 / 持久化影响（源 §1.2）。
- [ ] 0.3 交付物白名单：列出允许修改的目录；跨域缺口登记为依赖申报，缺功能改自己，禁止反向修改上游（源 §1.2）。
- [ ] 0.4 DoD 展开至少含：正向主链、负向输入、防连击、移动端视口、分角色登录、控制台与服务端日志零 ERROR，逐项预留证据位（源 §1.5）。凡参考原型开发：原型交互形态（流式、动画等）默认是验收项，做不到必须列为差异项**申报**，不允许静默简化（源 §1.5）。
- [ ] 0.5 链路含模型 → 加载 ai-feature skill。
- [ ] 0.6 框架/依赖大版本升级 → 先产出"行为漂移清单"（序列化默认值、驱动参数绑定、注入绑定规则、被移除/搬移的公共类），每项配一条最小验证，验证完再写业务代码（源 §4.5）。
- [ ] 0.7 新仓库/新目录初始化：治理规范随初始化同 commit 交付——两级 AGENTS.md、skill 目录、文档分区、结构与尺寸检查脚本；此后规范每次扩充都与检查脚本同 commit 更新（源 §1.1）。

### 阶段 1 · 实现（按变更类型套用子清单）

**通用契约**（源 §3.1、§3.5、§3.8）

- [ ] 写操作 = 幂等键（发起方每动作新生成，不跨动作复用）+ 乐观版本 + 专门化冲突错误码（幂等冲突 ≠ 版本冲突 ≠ 未授权 ≠ 不存在）；并发首击用 INSERT ON CONFLICT + 统一重读，禁止"先查后插"。
- [ ] 状态迁移与其关联字段的更新必须**同一语句**完成；用"枚举 × 服务分支"矩阵逐一对照——迁移表里定义了 ≠ 服务分支已实现。
- [ ] 撤回/取消/退回/驳回：先枚举该动作创建过的一切活动资源（审批实例、批次引用、锁、外部订单），逐项定义退出语义；测试必含"撤回→重提→再撤回"往返用例。
- [ ] 同一业务动作散在多条调用路径时提取**单一共享方法**——副作用（如费用计算）不允许只挂在其中一条路径上。
- [ ] 审计、通知等旁路写入用 REQUIRES_NEW 独立事务，不随业务事务回滚而丢失。
- [ ] 引用型字段（取值来自字典/目录/枚举表）由服务端校验归属并返回带字段名的错误；格式校验与引用校验分两栏逐字段核对。

**数据库**（源 §3.2、§1.4）

- [ ] 人工执行 SQL 四段结构：执行说明 / 只读 preflight / 有序变更 / 验证查询；完整基线同 commit 同步；已发布迁移不改写，部分应用状态用新增 repair 脚本（假设库处于任意中间态）；应用/测试/工具禁止自动执行任何 DDL/DML/种子。
- [ ] 显式 id 种子脚本尾部统一 `setval(pg_get_serial_sequence(...), max(id))`，写入增量与基线两处；建库后用一条真实 INSERT 验证自增可用。
- [ ] 查询行构造含可空列 → HashMap 手工 put，禁用 Map.of 等不可空容器。
- [ ] 幂等响应体存 text 不存 jsonb（jsonb 重排序键，破坏字节级重放语义）。

**前端**（源 §3.6、§3.7、§3.9、§5.1、§5.5、§5.6、§5.7）

- [ ] 每个写按钮带 busy 锁：点击即置 busy 置灰、请求返回才释放、失败恢复可重试。三层防重缺一不可：幂等键防重放、busy 锁防连击、业务唯一约束兜底防语义重复。
- [ ] 禁止 `.catch(() => [])` 式静默降级；每个数据页定义加载/空/失败三态；新端点先契约测试再接前端。
- [ ] 会话建立（登录/注册/恢复）时**显式保存**令牌为主路径；自动刷新只兜底"令牌过期"，必须带超时 + 单飞（并发去重）。
- [ ] 枚举与内部 ID 不直出——展示层做人类化映射（服务端输出枚举是正确契约，展示层映射不可缺位）；文案拼接显式管理边界字符，禁裸拼接。
- [ ] "数据性质/环境口径"类标识（演示/测试/样例）必须数据驱动贯通到展示层条件渲染，禁硬编码文案。
- [ ] 无权限的操作不渲染或禁用并说明原因（服务端授权照常保留——授权防越权，不渲染防无效交互）。
- [ ] 系统为用户生成的关键信息（一次性密码、回执号、恢复码）必须有对应**可见渲染元素**——后端 200 ≠ 用户可见。
- [ ] 表单控件的测试锚点用静态、与标签一致的字面量；禁用动态绑定值（`:placeholder="user.name"`）与 `text=` 模糊匹配。

**环境与基础设施**（源 §4.1、§4.2、§4.3、§4.4、§6.4）

- [ ] 环境差异（安全上下文/SSR/API 缺失）收敛到唯一共享适配点，禁业务代码散落环境判断；配置注入走框架标准机制，禁挂载改文件类 hack。
- [ ] 环境类修复（字体/依赖/端口/健康检查）五处联动：镜像/编排 → 运行时候选列表 → 配置注入点 → 示例配置 → 部署文档；缺一处下次环境重建即复发。
- [ ] CI/编排/网关文件每次修改：明确提交信息 + 提交前静态校验（语法 lint、重复块检测）+ 变更后一次真实构建。
- [ ] 过程日志按"归因"设计：多实例带 worker 标识、查找失败带全查找坐标、外部失败带连接坐标；每条为排障加的日志在注释里写明"防什么"。

**解析与展示**（源 §5.2）

- [ ] 解析器按"语义等价"接受多种结构形态，新增形态先写失败测试再扩展规则；错误提示列出全部可接受形态；字段抽取语义跨形态一致并写成断言。

### 阶段 2 · 验证（未跑的门禁 = 未通过）

- [ ] 2.0 写用例前先做探测式预检：对计划覆盖的每个能力逐个发请求 / 查代码存在性，先暴露缺口（端点缺失、纪律未贯彻、埋点为零、路由未守卫）→ 修复 → 再写用例。避免用例建立在未实现能力上产生假阳性（源 §7 深测轮）。
- [ ] 2.1 核对被测进程版本：修改后必须重启/重建再验证——测到旧 JVM/旧构建产生假阳性/假阴性。
- [ ] 2.2 缺陷修复带**同粒度**回归测试，写在缺陷暴露的同一层面，断言语义不快照；回答三问：缺陷如何被测试捕获 / 新测试断言什么 / 为何此前没拦住（第三问用于修补测试盲区）。
- [ ] 2.3 行为语义改进时同步更新既有测试的预期值——改进会让旧断言过期。
- [ ] 2.4 无 AI 冒烟主干随时可跑（stub 路径、逐步 PASS/FAIL、可重复可清理）；模型链路单独显式启用。
- [ ] 2.5 一切自动化批量修改逐条断言生效：替换后 grep 复核，防"看似改了实际没改"的静默 no-op。
- [ ] 2.6 UI 验证用**真实页面点击走查**——"组件能跑但没接进系统"（未注册路由、未合并数据源、入口缺失）只有点击能发现。断言三问：数据在哪渲染 / 以什么文本渲染 / 哪个角色能看到；断言绑渲染后的可见文本，不绑 HTTP 200 或组件挂载；跨轮残留数据用唯一后缀隔离，断言优先 API 校验兜底。
- [ ] 2.7 感知回归：桌面 + 移动两档、加载/空/失败/禁用四态、遮挡与裁切、控制台错误清零。交付物含演示录屏 → 旁白逐镜断言核对（说的每个入口/数字必须在画面真实可见）+ 注入浮层 pointer-events:none（源 §5.4）。
- [ ] 2.8 部署层行为（静态资源 404、SPA 回退、跨端跳转、反代路径）在**真实容器**验证，本地 dev server 不算数；修复根因写成配置文件内注释防误删。
- [ ] 2.9 共享环境破坏性用例（错误密码锁定、压测、清理）：专用牺牲对象（不碰主链路依赖实体）+ 脚本首行自愈重置；自愈失败显式报错不静默带病运行。
- [ ] 2.10 演示/种子数据：时间锚定用"应用时区今天固定时刻"（任何日期重跑落在本月）；历史素材按整月偏移铺满统计窗口（天数偏移跨月跳档）；种子自带清理段；重跑种子 → 逐页目检演练一遍。
- [ ] 2.11 未执行的验证在交付记录写明原因；状态用词表（已提出/已确认/已实现/已验证/已交付），不得混用。

### 阶段 3 · 收尾

- [ ] 3.1 diff 自查含感知层：枚举映射、文案边界字符、移动端断点、遮挡、空态。
- [ ] 3.2 决策/改名/范围变更全触点清扫：代码 + PRD + 原型 + 技术方案 + 接口描述 + 配置样例 + 前端文案；合并分支后专门扫"随合并进入的"残留。
- [ ] 3.3 环境类修复核对五处联动齐全（见阶段 1）。
- [ ] 3.4 按实际 diff 检查相关 skill 是否仍准确；仅在稳定工作流或不变量变化时更新，不随口改。
- [ ] 3.5 交付记录固定三字段：**验证命令及结果 / 未执行验证及原因 / 未解决风险**。

## 6. 环境与安全规则

- 不读取、不打印、不复制秘密值；只检查存在性。
- AI 工具的会话状态/记忆/缓存不入仓库；结论经整理写入正式文档目录才算仓库事实。
- 付费模型与外部付费服务的调用必须显式启用；普通单元测试不得触发。
- 破坏性操作（锁定、清理、压测）只对登记过的牺牲对象执行，登记污染面与重置方法。
- 数据库变更由人工执行；运行时缺结构显式失败，禁止静默自建或回退存储。
- 只读分析任务禁止 git 写操作。

## 7. 完成检查（全过才算完成）

1. 阶段 0–3 每个勾选项：已通过（附命令/截图/日志证据）或"未跑 + 原因"——无空白项；
2. 每个缺陷修复都有同粒度回归测试（能指出测试文件与断言）；
3. 每次批量修改都有生效断言（grep 复核记录）；
4. 交付记录三字段齐全，全文无"未验证写通过"；
5. 相关 skill 准确性已按 diff 核对；
6. 未解决事项全部列在"未解决风险"，不静默遗留。

## 附录 A · 项目栈特定坑（实证自 Java 21 / Boot 4.1 + PostgreSQL 18 + Vue 3 / Vite 8 项目，按需采纳，非通用规则）

- Boot 4.x 默认序列化切 Jackson 3（`tools.jackson` 包名），旧模块不自动注册；
- PG JDBC 拒绝无类型推断的时间参数 → 显式 `java.sql` 类型绑定；
- `@Value` 不做环境变量宽松绑定 → `@ConfigurationProperties` + yml 桥接；
- Boot 4 移除内建 `TestRestTemplate`；
- Vite dev server 默认绑 IPv6 → 显式 `server.host: '127.0.0.1'`，否则 127.0.0.1 fetch ECONNREFUSED；
- Docker Desktop 代理 socket 对 java 客户端 400 → Testcontainers `api.version` + raw sock，或改用"等价隔离实例" + `assumeTrue` 跳过（声明前提，不伪造结果）；
- jsdom 在 file:// 下 `history.replaceState` 抛 DOMException 中断进程 → `beforeParse` stub history API；
- Chrome headless 布局探针必须过滤 `display:none` 子树，否则 `getBoundingClientRect` 全 0×0 误报；
- Python `%` 格式化与 CSS `50%;` 冲突 → 占位符 `.replace()`；批量改 HTML 先取原始块再做替换，同一块多处改动合并成一次替换（先应用的替换会让后续旧锚点失效）。
