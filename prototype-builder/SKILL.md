# Prototype Builder（原型制作 Playbook）

核心认知：**幻觉 = AI 在未被指定的自由度里用"合理想象"填充。**
防御公式：事前锁死少数不变量 → 事中约束改动方式 → 事后用机器验证替代"看起来对"。
给不出的输入就列为待确认项，绝不让 AI 自行发明。

本 skill 按目标技术形态选择实现与验收手段；文中的单文件 HTML 骨架与浏览器门禁只是一种技术形态的示例，不设默认技术栈。

## Phase 0：开工前与用户对齐六类约束

逐项收集，缺项进入"待确认提问"，不开工（未确认的高影响自由度不开工）：

1. **对象模型**：实体 / 关系 / 身份标识规则 / 已知状态约束。每个视图先回答"面向哪个对象、服务何种任务"。
2. **术语表**：一个概念一个正式名、全文唯一；声明禁用旧称、检查范围与允许保留的历史引用。
3. **数据口径与规模**：演示对象数量、状态分布；所有展示数字必须能从明细复算；演示数据允许虚构但不得与既有事实矛盾。
4. **流程闭环边界**：每项能力有入口→操作→状态变更→出口；领域状态须可追溯责任角色与触发事件；门禁/解锁规则未定稿默认禁止；模拟能力显式标注演示态。
5. **参照物与视觉基调**：指定认可的参照原型/设计系统；未确认前不自行锁定风格。
6. **协作规则**：只做点名的事；决策点先问；模糊指代先确认对象；方向性指令（"放顶部/对齐"）先转译成参照+度量+位置的方案再执行；文档类产出默认更新既有文件。

## Phase 1：四项设计产物，人确认后再生成界面

1. **视图地图**：对象 → 视图形态 → 导航/路由结构；
2. **状态机**：领域状态枚举+合法转移；每态绑定默认视图和可用动作；终态可无后继，锁定态注明解除条件；
3. **术语表**：正式名称+禁用旧称+检查范围；
4. **演示数据表**：按 Phase 0 规模与事实约束填实。

**叙事总览页（可选，不计入四项产物）**：评审受众含非交互决策者、多版本并行竞标、或多端多视图原型时，可在四项产物确认后将其渲染为免登录叙事页（产品故事/模块图/闭环泳道/里程碑）；内容必须从 Phase 0 口径派生，不另立术语；标注演示态并列入正式版移除清单。单页 demo 或受众全是交互者时不做。

确认后再定实现骨架（不计入设计物）。单文件 HTML 可用 `state`/`VIEWS`/`ACTIONS` + 事件委托 + `render()/renderPartial()` + CSS 变量主题。提交策略=**一事一提交**。

## Phase 2：迭代中执行防幻觉十律

**管事实**
1. **单一事实源**：一个业务事实只存一处权威来源，各视图派生；跨视图状态声明 owner/作用域/持久化位置；实体与动作用稳定唯一 ID，展示名/数组位置/排序号不作主键。
2. **状态函数与异步隔离**：展示状态=f(data) 不存副本；操作状态按实体键化；异步请求带实体 ID+请求 ID+版本，回调写入前校验仍有效（过期/乱序/卸载的回调不得覆盖新状态）。
   - 字段生命周期：新增字段须明确来源、owner、类型、空值语义、读写入口、下游消费者；提交后验证保存、关闭重开回显、下游读取；改名/废弃时枚举迁移生产者与消费者。
   - 操作入口不把未计算/未确认的结果说成事实；预期数字须由权威数据派生并标为预期。

**管数字**
3. **可验算**：写数字前先验算，验收时必复算。

**管断言**
4. **必溯源**：断言定位到源码或状态并运行时复核；历史因果核父子版本 diff，会话因果须有会话记录；未经核实的指控（含外部评审）不采信。

**管改动**
5. **点名式执行**：未指定项按"模型能归属→用；不能→列待确认"，不发明；新增 UI 依赖先检索确认定义与许可。
6. **删功能连定义删净**：注册/样式/文案一起删；区分删呈现（保留有语义的数据）与删模型；删除前枚举消费方，共享代码只删目标分支；误删优先 `git show <hash>:<file>` 恢复，不凭记忆重写。
7. **迁移=源交互并集**：跨版本/技术形态迁移时枚举源体验全部用户可见能力逐项映射，不按"内容覆盖"裁剪。

**管上下文**
8. **重绘保持用户状态**：全量重绘保留滚动/展开/焦点；跨页返回、刷新后从权威来源恢复状态。
9. **全局同步与派生重算**：术语/流程变更按声明范围同步；结构重排后编号序号重算；批量重命名用旧→新映射禁止顺序子串替换；共用键校验值域白名单；跨页状态更新有刷新/失效策略。

**管基线**
10. **并行编辑先核基线**：动手前 git status/diff+提交图；提交图只证明提交关系，并行因果须会话证据。

## Phase 3：三道门验收（不通过不交付）

| 门 | 手段 | 抓什么 |
|---|---|---|
| 门 1 静态 | 按技术形态跑对应静态检查（单文件 HTML 用下方示例脚本）；函数调用↔定义清单另用 AST/人工核对 | 语法错误、静态死按钮、缺失视图引用、区间编辑丢定义 |
| 门 2 行为 | 浏览器/运行时实测关键路径、状态转换、实体切换后回调、跨页返回刷新；监听 error/unhandledrejection；表单用自定义值提交后核对保存与回显 | 运行时错误、状态不可达/串扰、过期回调、字段未保存未回显 |
| 门 3 用户视角 | 独立 judge 逐页截图+按明示公式和舍入精度复算数字（明细加权≈总分、分类计数=总数、跨页一致） | 错位/截断/重叠、明细与汇总矛盾、跨页状态不一致 |

门 3 要点：验算规则写进 judge 指令并要求报告页面+字段+实际值+预期值；judge 读不了图按预定回退流程人工逐页查；断言必须绑定本次改动的新行为（旧 DOM/缓存不算证据）；断言限定在实际内容容器，勿把源码字符串当已渲染。

### 门 1 示例脚本（仅适用于：单文件 HTML、经典内联脚本、静态双引号 data-action/data-view、ACTIONS 键单行一个前导空格、VIEWS["..."] 注册跳转目标）

只比对静态 action 键与静态视图注册，不证明键值可调用，不解析任意 JS；单引号/动态属性/运行时注册/其他路由机制/函数调用↔定义/外部脚本/module 须另做 AST/人工/浏览器核查。其他技术形态换成对应检查。

```bash
set -euo pipefail
file="${1:-原型.html}"
command -v node >/dev/null || { printf '%s\n' "FAIL: Node.js 未安装" >&2; exit 1; }
test -f "$file" || { printf 'FAIL: 找不到 %s\n' "$file" >&2; exit 1; }
tmp="$(mktemp -d)"
trap 'rm -rf "$tmp"' EXIT

# 语法：只抽取经典内联脚本；module/外链脚本需另行检查。
node - "$file" <<'NODE'
const fs = require("fs");
const source = fs.readFileSync(process.argv[2], "utf8");
const scripts = [...source.matchAll(/<script\b([^>]*)>([\s\S]*?)<\/script\s*>/gi)]
  .filter(m => {
    const attrs = m[1];
    if (/\bsrc\s*=/i.test(attrs)) return false;
    const type = attrs.match(/\btype\s*=\s*(?:"([^"]*)"|'([^']*)'|([^\s>]+))/i);
    const kind = type ? (type[1] || type[2] || type[3]).toLowerCase() : "";
    return !kind || kind === "text/javascript" || kind === "application/javascript";
  });
if (!scripts.length) throw new Error("未找到可检查的经典内联脚本");
new Function(scripts.map(m => m[2]).join("\n"));
console.log("SYNTAX PASS");
NODE

# 静态 action 键差集。仅支持双引号静态属性和标准 ACTIONS 对象键。
perl -ne 'while (/data-action="([^"]+)"/g) { print "$1\n" unless $1 =~ /\$|\+/ }' "$file" | sort -u > "$tmp/used"
perl -0777 -ne 'if (/const\s+ACTIONS\s*=\s*\{([\s\S]*?)\n\};/) { my $body = $1; while ($body =~ /^ "([a-z][a-z0-9-]*)"\s*:/gm) { print "$1\n" } } else { die "ACTIONS 表未找到\\n" }' "$file" | sort -u > "$tmp/defined"
comm -23 "$tmp/used" "$tmp/defined" > "$tmp/missing"
comm -13 "$tmp/used" "$tmp/defined" > "$tmp/unreferenced"
if test -s "$tmp/missing"; then printf '%s\n' "FAIL: action 无定义"; cat "$tmp/missing"; exit 1; fi
if test -s "$tmp/unreferenced"; then printf '%s\n' "WARN: 未被静态引用的 action（人工判断是否为动态调用）"; cat "$tmp/unreferenced"; fi
perl -ne 'while (/data-view="([^"]+)"/g) { print "$1\n" unless $1 =~ /\$|\+/ }' "$file" | sort -u > "$tmp/views-used"
perl -ne 'while (/data-view="([^"]+)"/g) { print "$1\n" if $1 =~ /\$|\+/ }' "$file" | sort -u > "$tmp/views-dynamic"
perl -0777 -ne 'my $s = $_; while ($s =~ /VIEWS\["([^"]+)"\]\s*=/g) { print "$1\n" }' "$file" | sort -u > "$tmp/views-defined"
comm -23 "$tmp/views-used" "$tmp/views-defined" > "$tmp/views-missing"
if test -s "$tmp/views-missing"; then printf '%s\n' "FAIL: 静态跳转目标无视图定义"; cat "$tmp/views-missing"; exit 1; fi
if test -s "$tmp/views-dynamic"; then printf '%s\n' "WARN: 动态跳转值需人工/运行时核查"; cat "$tmp/views-dynamic"; fi
printf '%s\n' "STATIC ACTION AND VIEW CHECK PASS"
```

## 交付自检清单（C01–C26，按改动类型选用）

界面/流程改动至少覆盖 C01-C05、C08-C09、C11-C13、C16-C18、C20-C21、C24-C26；删除/恢复另核对 C06-C07、C19；字段改名核对 C10；术语/流程改名核对 C14；结构重排核对 C15；并行编辑核对 C22；方向性指令核对 C23。

- C01 新数字能按明示公式和舍入精度从明细复算吗？
- C02 每条新断言有可定位来源，或显式标注"待补"吗？
- C03 状态变更后，所有派生视图都从同一权威来源更新了吗？
- C04 每个非终态可达且有合法后继吗？终态/锁定态的不可退出性或解除条件已说明吗？
- C05 操作/提交状态按所属实体 keyed，异步回调有实体 ID、请求 ID 和版本校验吗？
- C06 删除前枚举过消费方吗（共栖分支只删目标分支）？
- C07 误删/回滚优先从 git 历史恢复了吗？并行因果有提交图或会话证据支持吗？
- C08 表单提交值与用户输入一致，且关闭重开后能回显吗（value/data-* 读值来源正确）？
- C09 每个字段都明确来源、owner、类型、空值语义、默认值、保存位置、读写入口和下游消费者吗？
- C10 字段改名/废弃时已枚举并迁移生产者、消费者和历史数据吗？
- C11 实体、子实体、动作和异步请求都有稳定唯一 ID；展示名、数组位置、排序号未被当作主键吗？
- C12 生命周期变化后，界面切到该状态绑定的默认视图了吗？
- C13 跨页面/端视图按稳定实体 ID 读取同一权威状态；进入、返回、刷新和直接打开路由后仍一致吗？
- C14 改名/改流程后，在明确文件范围内检索旧术语并做词边界与上下文抽查了吗？历史材料等例外已列明吗？
- C15 结构重排后，编号/序号/文案等派生值按新结构重算了吗？
- C16 模拟交互显式标注演示态，没有伪造已落库或已生效状态吗？
- C17 共用数据的不同概念在展示层分语境命名了吗（数据同源≠称谓同源）？
- C18 每个按钮都有明确出口或可观察的局部状态变化吗？未接后端的动作已标明演示态吗？
- C19 删除功能时连定义、动作注册和样式一起核对了吗？仅删呈现时模型字段保留了吗？
- C20 函数调用↔定义、静态 action↔动作表键、跳转目标清单核过了吗？动态项及 handler 可调用性已人工/AST/运行时检查吗？
- C21 批量替换逐处唯一锚定了吗？CSS/结构手术后的语法、括号、选择器和唯一键检查通过了吗？
- C22 动手前核对过 git 基线与并行改动归属了吗？
- C23 方向性/相对性指令已转译成参照、度量和位置明确的方案并确认了吗？
- C24 操作入口没有将未计算或未确认的结果说成事实；若显示预期数字，是否由权威输入动态派生并明确标为预期？
- C25 大改前盘点的回归清单逐项核对了吗？
- C26 三道门（静态/行为/用户视角）都通过并留有证据吗？

## 红线（违反即停）

- 未指定即提问，不发明；未确认不开工。
- 字段和状态须有稳定身份、唯一事实源及可核对读写链。
- 门禁未定稿默认禁止；演示态必须明示。
- 项目案例/历史复盘只是参考，不能替代当前项目的 PRD、口径表和代码基线。

```markdown
## 工作方式
1. Phase 0 先收集约束；写界面前输出四项产物等确认：①视图地图 ②状态机 ③术语表 ④演示数据表。

3. 只做本次点名的事；改进建议单列，不擅自实施。
4. 决策点先确认；模糊指代和相对位置指令先转译成具体方案再确认。

## 红线
1. 字段须有来源、owner、稳定 ID、读写入口和消费者；字段提交后核对回显与跨页读取。
2. 展示状态由数据派生；操作状态按实体隔离；异步回调校验实体、请求和版本；数字按明示公式复算。
3. 删除前枚举消费方；删功能时核对定义/动作/样式，误删优先从 git 历史恢复。
4. 演示态必须明示；结构重排后重算派生值；跨页视图读取同一权威状态。
5. 文档类产出先查同类文件，默认更新或追加；整体覆盖、删除或改名须明确授权。

## 交付前自检

```
