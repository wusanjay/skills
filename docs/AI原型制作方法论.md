# AI 产品原型制作：通用方法论与核心原则

> **定位**：面向 AI 辅助制作高保真、可交互数字产品原型的可复用 Playbook，覆盖立项对齐、迭代约束和交付验收。各技术栈应采用对应的实现与验收手段；文中单文件 HTML 与浏览器门禁仅为一种技术形态的可选示例。
> **边界**：本文不替代具体产品的 PRD、术语表、数据模型或技术规范；项目案例为可选参考，不属于本方法论或 Skill 的必需资产。
> **用法**：Phase 0 的六类约束 + 初始提示词模板在开工时使用；Phase 1 四项产物确认后再生成界面；十律在每轮迭代中执行；三道门在每轮交付前过；第六节可蒸馏为 SKILL.md。

---

## 〇、一个核心认知

**本方法论所说的幻觉 = AI 在未被指定的自由度里，用"合理想象"填充。**

防御不是把一切讲清（不可能），而是：
**事前锁死少数不变量 → 事中约束改动方式 → 事后用机器验证替代"看起来对"。**

常见风险符合这个公式：对象模型未定会导致无依据字段，术语未对齐会造成改名残留，派生规则缺失会使视图各自维护状态，缺少机器验收则让数据矛盾依赖人眼发现。先确认能降低返工，但不能保证零返工，仍须逐轮验证。

## 一、Phase 0 立项对齐：开工前必须指定的六类约束

> Phase 0 收集用户决策与约束，不要求用户预先产出完整设计物。给不出的内容就是**未指定自由度**，必须列为待确认项而不是自行发明。

### 1. 对象模型（实体 / 关系 / 状态约束）
先定"有什么东西"，再定"如何呈现与操作"。Phase 0 指定对象边界、关键关系、身份标识规则与已知状态约束；Phase 1 再把它们整理为状态机。列表、详情（含弹窗/抽屉）和画布/工作台是常见视图形态，不构成完整枚举；每个视图先回答"面向哪个对象、服务何种任务"。
- 防什么：界面元素无处落位（无设计依据自造字段）、按概念分页而非按对象组织、展示名称或数组位置被误作身份标识、**共用数据吞掉概念分层**（数据同源 ≠ 称谓同源）、**UI 元素角色错位**（控件未标注服务对象与阶段）。
- 对象模板见附录 B。

### 2. 术语表
一个概念一个正式名，全文唯一；**口语比喻只留在讨论里，不进界面**。
- 防什么：口径漂移、改名残留、非正式表达进入产品界面或交付文档。
- 演化规则：术语表随产品现状更新；历史材料不是当前术语来源，隔轮或跨会话生成前先对齐当前术语表。
- 改名检查须先声明纳入范围（原型、源文档、测试和构建产物等）及例外（历史记录、术语迁移表、明确引用）；对可改范围按裸词/词边界检索，报告残留位置并做读值抽查。计数清零只表示该检索规则下无命中，不等于语义层面绝对干净；非零命中须人工判断。

### 3. 数据口径与规模
指定演示对象规模、状态分布与数据来源约束；Phase 1 据此整理演示数据表。**所有展示数字必须能从明细复算**；加权值按明示公式核对；允许的舍入误差应按公式精度、展示精度及汇总方式预先定义。百分比合计可因逐项舍入而偏离 100%，容差须按项数和精度计算并记录，不使用无依据的固定容差。**演示数据允许虚构，但必须与已建立的事实网络一致**，不得与既有状态或历史记录矛盾。
- 防什么：AI 编造数字、汇总与明细对不上、对象样本不足以覆盖计划中的视图与状态。

### 4. 流程闭环边界（MVP）
明确每项能力的完整闭环走向（入口→操作→状态变更→出口）；**领域状态必须能追溯到责任角色、触发事件与判定条件**；流程步骤不得由 AI 擅自增加；明确不纳入本期的范围；**门禁/解锁规则未定稿时默认禁止**，列入待确认；**模拟能力与真实能力显式区分**，不得伪造持久化或后端生效结果。
- 防什么：无可执行出口的功能、目标不可达、未确认的状态转移和未接入能力被表现为已生效。

### 5. 参照物与视觉基调
指定一个认可的参照物、设计系统或视觉方向（配色/组件风格/布局密度），让 AI 按目标技术栈提取可复用的主题变量与组件规范。
- 防什么：视觉基调来回摇摆、AI 自创风格不符预期。
- 建议：在实现前确认一个认可的参照物；尚未确认时，先列出视觉方向待决项，不自行锁定风格。

### 6. 协作规则
**只做点名的事**；自己发现的改进点列入"待确认建议"不得直接实施；**决策点先确认**；**模糊指代先确认对象**；**方向性/相对性指令先转译成可验证方案**，明确参照、度量与位置关系后再执行。文档/分析类产出先查同类文件，默认更新或追加；新增文件须有明确产出需求。默认更新不授权整体覆盖、删除或改名；破坏性操作须被明确要求。

## 二、Phase 1 骨架与地基（AI 生成，人确认后再写界面）

Phase 0 给出决策输入；Phase 1 将其整理为四项可审阅产物，**人确认后再生成界面**：

1. **视图地图**：对象 → 视图形态 → 导航/路由结构；列出本项目实际采用的视图，不预设完整形态枚举；
2. **状态机**：领域状态枚举、合法转移动作与条件；每个领域状态绑定默认视图和可用动作。终态可无后继；锁定态须注明解除条件或不可解除理由；
3. **术语表**：每个概念一个正式名称，标注禁用旧称及检查范围；
4. **演示数据表**：按 Phase 0 规模、状态分布与事实网络约束填实。

**叙事总览页（可选，不计入四项产物）**：评审受众含非交互决策者、多版本并行竞标、或多端多视图原型时，可在四项产物确认后将其渲染为免登录叙事页（产品故事/模块图/闭环泳道/里程碑）；内容必须从 Phase 0 口径派生，不另立术语；标注演示态并列入正式版移除清单。单页 demo 或受众全是交互者时不做。

四项确认后再按目标技术栈定实现骨架；技术选型和架构草案是实现约定，不计入四项设计产物。若采用单文件 HTML，可用 `state`（唯一事实源）+ `VIEWS` + `ACTIONS`、document 级事件委托、`render()` / `renderPartial()` 和 CSS 变量主题。提交策略为**一事一提交**，便于回滚和并行核对。

## 三、Phase 2 迭代循环：防幻觉十律（每轮改动中执行）

每轮大改动手前，先 `grep` 盘点将触碰的函数/样式全集，列**回归清单**，交付时逐项核对。以下十律在改动中执行：

**管事实**
1. **单一事实源**：一个业务事实只存一处权威来源；各页面、摘要、状态标识和统计从同一模型派生。跨视图状态须声明 owner、作用域与持久化位置，禁止各视图各存一份业务状态。实体、子实体、动作和异步请求使用各自命名空间内稳定唯一的 ID；展示名称、数组位置和排序号不得充当主键。
2. **状态函数与异步隔离**：领域状态描述对象生命周期及合法转移；操作状态描述某实体上的提交/评估等过程；展示状态是由数据派生的 UI 表达，不另存业务事实；门禁是基于当前状态和规则对动作的允许/拒绝判定；演示态标明仅为原型模拟。操作状态按所属实体键化。每个异步请求携带实体 ID、请求 ID 和发起时版本；回调写入前校验请求仍有效，过期、乱序、重复、取消或卸载后的回调不得覆盖新状态。
   - **字段生命周期**：新增或改动字段须明确来源、owner、类型、空值语义、默认值、读写入口、适用状态、保存位置及下游消费者；提交后验证保存、关闭重开回显和下游读取。字段改名/废弃时枚举并迁移所有生产者与消费者。
   - **操作入口不把未计算/未确认的结果说成事实**：入口文案优先描述动作；若结果规模已由输入或计划确定，可标注为预期值，但须从权威数据动态派生，不能复制硬编码。

**管数字**
3. **可验算**：写数字前先验算，验收时必复算；AI 最擅长编合理数字，验算是唯一解药。

**管断言**
4. **必溯源**：代码/运行状态断言须定位到源码或状态，并在适用时运行时复核；历史因果须核父子版本与 diff，会话因果须有会话记录。对未经核实的自我判断或外部评审指控不直接采信。

**管改动**
5. **点名式执行**：只做被点名的事；未指定项按“已有模型能否支持 → 有据可依则使用；无法归属则列待确认”处理，不发明新概念。
   - 新增 UI 依赖（函数/类名/图标/资产/样式）先检索并确认定义、可用范围和许可条件，不凭记忆假设。
6. **删功能连定义删净**：函数/动作注册/样式/文案一起删，不留死代码、死按钮、死样式。区分删除 UI 呈现与删除业务模型：仅移除呈现时保留仍有语义的数据；删除整个功能时才一并删除模型定义。
   - **删除前先枚举消费方**：检索目标函数、字段、样式的全部引用点；共享函数或样式只删目标分支。
   - 使用文本编辑工具删行前检查行尾及同行注释，避免把注释拼接到相邻代码。
   - **误删/回滚优先从 git 历史恢复旧实现**（`git show <hash>:<file>` 抽取回填），不凭记忆重写；Git 提交图只证明提交与父子关系，并行会话因果须有会话记录佐证。
7. **迁移 = 源交互并集**：跨版本或跨技术形态迁移时，先枚举源体验的全部用户可见能力与交互（导航、展开、定位、编辑、提交及失败状态），逐项映射到目标实现；未经确认不按“内容覆盖”自行裁剪。

**管上下文**
8. **重绘保持用户状态**：全量重绘必须保留滚动位置/展开态/焦点；输入类交互尽量避免无必要重绘，防止内容丢失。跨页返回、刷新和直接打开路由后，选中实体与状态必须从权威来源恢复。
9. **全局同步与派生重算**：术语/流程变更后按定义的文件范围同步；结构重排后由新结构重算编号、序号和文案。批量重命名用旧→新映射并按稳定 ID 更新引用，禁止顺序子串替换；手术后检查 ID、选择器、动作键、状态值域和语法。对象字面量重复键会静默覆盖，跨视图共用键须校验值域白名单。跨页状态更新须明确刷新/失效策略，禁止其他视图继续显示已过期副本。

**管基线**
10. **并行编辑先核基线**：多会话 / fork 并行修改同一文件时，动手前检查 git status/diff、提交图和未提交改动；确认改动归属与基线后再处理重叠功能，不双写、不误删。提交图只能证明提交关系，并行因果须另有会话证据。

## 四、Phase 3 验收门禁：三道门（不通过不交付）

| 门 | 手段 | 抓什么 |
|---|---|---|
| 门 1 语法 + 静态引用 | 对约定支持的经典内联脚本做语法解析；静态核对 `data-action` 值与 `ACTIONS` 键、静态跳转目标与注册视图/路由。handler 是否可调用、函数调用↔定义清单须另用 AST/人工/运行时核对；示例正则不解析任意 JavaScript | 语法错误、静态死按钮、缺失视图引用；区间编辑造成的相邻定义丢失 |
| 门 2 行为 | 浏览器实测关键路径、状态转换、实体切换后的异步回调、跨页返回/刷新；监听 `error` 与 `unhandledrejection`；表单自定义输入后核对保存值及重开回显 | 运行时错误、状态不可达/误串扰、过期回调覆盖、字段未保存或未回显 |
| 门 3 用户视角 | 独立 judge 逐页截图验收，并按明确公式和舍入精度复算数字 | 错位/截断/重叠、明细与汇总矛盾、跨页状态不一致 |

**门 3 要点**：
- 将验算规则写入 judge 指令，要求报告页面、字段、实际值和预期值；judge 是辅助检查，不能替代明确的验算公式与人工复核。
- 若 judge 无法读取或渲染截图，按预定回退流程由主验收者逐页检查，并记录回退原因和覆盖范围。
- 浏览器自动化遇到 locator 超时、缓存或视口限制时，优先用稳定选择器和明确视口重试；任何回退方法都须确认实际作用于目标页面与目标版本。
- **验证断言必须绑定本次改动的新行为**：旧 DOM、缓存或残留内容不能证明改动生效；先确认页面使用新版本，再断言目标行为。
- **断言范围限定渲染层**：页面文本断言应查询实际内容容器或 DOM 节点，避免将源码、脚本字符串或隐藏模板误判为已渲染内容。

**门 1 示例脚本（有限静态检查；需与原型约定保持一致）**：

以下脚本只适用于 `原型.html` 含经典内联脚本、静态双引号 `data-action`/`data-view`，且 `ACTIONS` 键各自独占一行、使用一个前导空格和双引号，并以 `VIEWS["..."]` 注册跳转目标的约定。它只比对静态 action 键和静态视图注册，不证明键值可调用，也不解析任意 JavaScript；注释/字符串中的伪属性、单引号/动态属性、运行时注册、其他路由机制、函数调用↔定义、外部脚本和 module 须另做 AST/人工/浏览器核查。若原型采用其他技术形态，应替换为该形态对应的静态检查。语法检查只解析经典内联 JS；遇到其他 script 类型应单独检查，不得视为已覆盖。

```bash
set -euo pipefail
file="${1:-原型.html}"
command -v node >/dev/null || { printf '%s\n' "FAIL: Node.js 未安装" >&2; exit 1; }
test -f "$file" || { printf 'FAIL: 找不到 %s\n' "$file" >&2; exit 1; }
tmp="$(mktemp -d)"
trap 'rm -rf "$tmp"' EXIT

# 语法：只抽取经典内联脚本；module/外链脚本需另行检查。
node - "$file" <<'NODE'
const fs = require("fs");
const source = fs.readFileSync(process.argv[2], "utf8");
const scripts = [...source.matchAll(/<script\b([^>]*)>([\s\S]*?)<\/script\s*>/gi)]
  .filter(m => {
    const attrs = m[1];
    if (/\bsrc\s*=/i.test(attrs)) return false;
    const type = attrs.match(/\btype\s*=\s*(?:"([^"]*)"|'([^']*)'|([^\s>]+))/i);
    const kind = type ? (type[1] || type[2] || type[3]).toLowerCase() : "";
    return !kind || kind === "text/javascript" || kind === "application/javascript";
  });
if (!scripts.length) throw new Error("未找到可检查的经典内联脚本");
new Function(scripts.map(m => m[2]).join("\n"));
console.log("SYNTAX PASS");
NODE

# 静态 action 键差集。仅支持双引号静态属性和标准 ACTIONS 对象键。
perl -ne 'while (/data-action="([^"]+)"/g) { print "$1\n" unless $1 =~ /\$|\+/ }' "$file" | sort -u > "$tmp/used"
perl -0777 -ne 'if (/const\s+ACTIONS\s*=\s*\{([\s\S]*?)\n\};/) { my $body = $1; while ($body =~ /^ "([a-z][a-z0-9-]*)"\s*:/gm) { print "$1\n" } } else { die "ACTIONS 表未找到\\n" }' "$file" | sort -u > "$tmp/defined"
comm -23 "$tmp/used" "$tmp/defined" > "$tmp/missing"
comm -13 "$tmp/used" "$tmp/defined" > "$tmp/unreferenced"
if test -s "$tmp/missing"; then printf '%s\n' "FAIL: action 无定义"; cat "$tmp/missing"; exit 1; fi
if test -s "$tmp/unreferenced"; then printf '%s\n' "WARN: 未被静态引用的 action（人工判断是否为动态调用）"; cat "$tmp/unreferenced"; fi
perl -ne 'while (/data-view="([^"]+)"/g) { print "$1\n" unless $1 =~ /\$|\+/ }' "$file" | sort -u > "$tmp/views-used"
perl -ne 'while (/data-view="([^"]+)"/g) { print "$1\n" if $1 =~ /\$|\+/ }' "$file" | sort -u > "$tmp/views-dynamic"
perl -0777 -ne 'my $s = $_; while ($s =~ /VIEWS\["([^"]+)"\]\s*=/g) { print "$1\n" }' "$file" | sort -u > "$tmp/views-defined"
comm -23 "$tmp/views-used" "$tmp/views-defined" > "$tmp/views-missing"
if test -s "$tmp/views-missing"; then printf '%s\n' "FAIL: 静态跳转目标无视图定义"; cat "$tmp/views-missing"; exit 1; fi
if test -s "$tmp/views-dynamic"; then printf '%s\n' "WARN: 动态跳转值需人工/运行时核查"; cat "$tmp/views-dynamic"; fi
printf '%s\n' "STATIC ACTION AND VIEW CHECK PASS"
```

- 门 2：进入页面后监听 `error` 与 `unhandledrejection`，走查关键路径；用自定义表单值提交，关闭重开核对回显；切换实体并等待异步回调，确认旧请求不覆盖新状态。
- 门 3 judge 指令模板：逐页截图；按明示公式和舍入精度验算明细、汇总、分类计数和跨页状态；发现矛盾逐条报告页面、字段、实际值与预期值。

## 五、每轮交付自检清单（复制使用）

> 本清单是完整交付检查的唯一事实源，编号为附录 A 引用锚点；附录 A 只选开工必需子集，不逐句复制规则。

- [ ] C01 新数字能按明示公式和舍入精度从明细复算吗？
- [ ] C02 每条新断言有可定位来源，或显式标注"待补"吗？
